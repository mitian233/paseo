# MyGo 桌面 UI 重构方案

## 依据与范围

用户的视觉反馈是：按照 Electron 中 React Native 前端的结构，用 MyGo UI 实现，不自行设计另一套工作台。原版指当前仓库 `packages/app` 在 Electron 中实际使用的桌面布局；手机布局不作为桌面基准。现有 MyGo 的连接表单、agent 按钮列表和通用消息列表是验证界面，不作为目标设计。

重构保留已验证的 Go daemon 客户端、请求关联、订阅归属和发送结果未知语义。daemon 仍是既有服务，不增加协议或进程管理职责。Mermaid 按最新用户决定暂停，保留现有实现与缺陷记录；语音、插件客户端、网页面板、浏览器自动化继续延期。本方案不改变完整替代的其他功能范围，也不将未实现的终端、文件、Git/PR 能力称为已完成。

这是整个原生工作台的 UI 重构，按依赖分批完成；第一批的通过不代表完整桌面替代。原方案已于 2026-11-05 获批并实施了一部分。2026-11-10 根据用户对首页与边栏的反馈重新核对源码，补齐下文落地方案；当前首页与边栏未通过对齐验收。

## 目标界面与状态

工作台保持原版的拓扑：应用导航在左；工作区内容包含自己的顶栏、标签栏、面板内容和会话输入区；Explorer 作为可开关的独立停靠区；普通侧面打开的内容属于工作区分栏。面板中的会话可与其他真实内容并列，不将所有内容塞进一个全局聊天页。

没有主机时显示原版连接引导；连接中、连接失败、主机不可达、没有工作区、未打开标签和历史加载失败各有对应状态。只有添加/编辑主机时展示连接参数。错误呈现在其所属主机、标签或会话内，不用一个全局 status 字符串覆盖所有状态。

权限请求的位置和展开方式以原版桌面渲染为准，去掉当前独立 JSON 展示框。工具行先显示原版摘要、图标和状态；展开后按类型显示命令、输入、输出、错误或 diff，保留可复制的详情。无法识别的工具类型仍须提供原版等价的可读详情，不能丢失数据。

输入区使用原版多行编辑结构，发送快捷键、换行、停止、输入法组合输入和禁用状态均单独核对。模型、模式、附件等控件只在真实协议能力和对应实现完成后出现，不放置不能操作的装饰按钮。

## 原生组件与状态归属

界面使用 MyGo 的 UI 组件、布局、主题和样式接口，由 MyGo 负责渲染。Go 代码组合这些组件，实现 Paseo 的导航行、标签、工具卡、权限卡与 composer。不会绕过 MyGo 自建绘制器，也不通过操作系统绘图接口另写一套 UI。保留原版的信息结构和交互。

先建立供本轮界面使用的最小 token 与组件组合：导航行、图标工具按钮、标签、文本输入、弹窗框架、状态标识。配色、尺寸、间距和状态通过 MyGo 已有样式接口配置。先核实安装版本的组件能力；不能直接表达的原版细节单列差异及影响，不擅自改成自绘控件或其他 UI 框架。

从 `workbench/app.go` 分出窗口外壳、导航、工作区/标签宿主、会话、输入和权限视图。`App` 只组装并管理窗口入口。已有 client/protocol 层继续负责通信。

状态按主机、工作区、标签/agent 建立稳定身份。每个会话保存自己的草稿、滚动锚点、工具展开状态、发送尝试与权限状态；切换标签不清空草稿、不串消息、不丢未确认请求。主题或尺寸变化只改变呈现，不重建连接与订阅。视图释放与后台需求释放分开；不通过保留所有历史视图实现状态保存。

当前 timeline 的文本条目继续服务消息渲染，工具、附件和权限展示需要保留结构化数据。若现有 Go 投影只留下拼接后的 JSON 字符串，应在投影处保留现有协议字段，避免 UI 反向解析展示文本；不扩展 wire schema。

## 尺寸与视觉规则

取值依据是当前原版 token，而不是这次重新挑选：桌面界面字号默认 14，正文默认 15，代码字号独立；主导航偏好宽度 320，最小 200，中心内容目标至少 400；Explorer 至少 240，工作区至少 360。主导航在空间不足时让位，不能把三列压成窄条。临时宽度钳制不覆盖用户保存宽度。

600 是既有 compact/wide 边界；工作区内部另有内容宽度预算。桌面窗口缩小时沿用原版导航与面板让位规则，不新增一个固定三列断点。指针控制默认高度 32、紧凑工具控制 28，触控控制使用原版对应尺寸。标题层级主要来自字重与颜色，不使用当前 20px 的独立 Paseo 大标题重建层级。

配色、背景层级、边框、圆角、图标与 hover/pressed/selected/disabled 状态都从 `theme.ts` 和原版基础控件核对迁移。支持系统、浅色与深色选择。平台差异仅限窗口控制、菜单、输入法、文件对话框等必要系统边界。

## 首页与边栏对齐落地方案（2026-11-10 修订）

### 基准与已发现的错误

目标仍是现有 Electron 中的 RN 界面，不重新设计导航。已有浏览器截图只能辅助检查内容区，不能证明窗口外壳一致。此前“边栏结构已完全对齐”的结论撤回：只显示 New workspace、隐藏三个缺失入口，属于未完成。

本次核对依据：`components/left-sidebar.tsx` 的 DesktopSidebar、SidebarFooter；`components/sidebar/sidebar-nav-rows.tsx`、`sidebar-header-row.tsx`、`empty-states.tsx`；`sidebar-nav/model.ts`；`screens/open-project-screen.tsx`。路径均相对 `packages/app/src`。

| 区域          | 当前原生实现的差距                                                        | 实施要求与主要落点                                                                                                                                                      |
| ------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 顶部窗口区域  | `desktopui/shell.go` 无条件插入 36px 空行，并错误地把空行注释为可拖动区域 | RN 仅在拥有左上角窗口 chrome 或显示开发标记时插入 chrome 行；TitlebarDragRegion 本身是绝对定位覆盖层。按实际窗口所有权决定占位；原生拖动须接窗口 API，不能靠空 Row 代替 |
| 顶部导航      | History、Search、Schedules 回调未接，按 nil 被隐藏；无当前页面选中状态    | 默认顺序保持 New workspace、History、Search、Schedules；可见性与排序属于用户偏好，不能由实现是否完成决定。所有默认入口完成真实目的地后统一验收                          |
| New workspace | `workbench/navigation_actions.go` 把它直接接到 Add project                | 保留主机、项目与源目录上下文，进入原版新建工作区选择流程；区分已有项目新建工作区与添加项目，不能调用 newAgent 或用 Add project 冒充                                     |
| 空项目区      | 只有两行文字                                                              | 迁移原版空状态卡的边框、内距、标题/说明层级、Add project 和 Import session 两个真实动作；保留列表拥有的标题与显示菜单，不用空状态替换整个列表                           |
| 有项目区      | 简化的项目→工作区→活动 agent 树                                           | 对照 SidebarWorkspaceList 的实际分组模式、置顶、折叠、活动行、未读/运行状态、上下文菜单及过滤结果；不把原生额外的 agent 子行当成原版默认结构                            |
| 底栏          | Usage 缺失；Hosts 被放到空白之后；Help 是无动作按钮；主机菜单仅切换主机   | 固定底部图标顺序：Add project、Usage、Hosts、伸缩空白、Help、Settings。Hosts 保留连接状态、添加和主机设置；Help 接原版帮助菜单。Usage 图标与可选 Usage 汇总行分开处理   |
| 导航行状态    | 只有 hover，图标为手写近似路径                                            | 使用原版图标路径、语义颜色、hover/pressed/selected/focus 状态；快捷键提示与真实路由使用同一绑定；不以近似 calendar 图标替代 CalendarClock                               |
| 首页主体      | 三卡截图不能覆盖四卡、主机错误、窄窗口；文字换行与字体仍有差异            | 对齐 logo、卡片网格、字体/行高、底部链接和主机错误归属；三卡与四卡分别检查。Pair device 的能力门控沿用已记录的原生差异，不能将差异称为原版一致                          |

### 实施顺序与交付边界

1. **冻结可比较的基准。** 在隔离 daemon 中建立空项目、含项目与工作区、运行/未读状态、离线主机的固定数据。记录窗口内容尺寸、DPR、缩放、主题、字体、导航宽度、偏好、窗口 chrome 所有权。先取得真实 Electron 基准；若运行受阻，记录具体阻碍，源码研究可以继续，但窗口对齐不可判通过。
2. **补目的地和状态模型。** `workbench` 负责 Home/History/Schedules 等应用级目的地与返回行为，Command center 作为覆盖层；它们不伪装成工作区标签。主机/工作区/agent 的稳定身份继续沿用现有状态。切换页面保留工作区标签与草稿；切换主机或关闭页面后，旧请求不得写入新目的地。
3. **完成顶部四入口。** New workspace 先补上下文选择流程；History 接真实会话历史、主机筛选、搜索、游标分页和打开会话；Search 打开原版语义的 Command center，支持查询、键盘选择、执行及 Escape 返回；Schedules 接真实列表、筛选、表单、修改/启停/删除及错误反馈。导航入口与目的地同批交付，不先留空页面或隐藏入口交差。
4. **迁移边栏三段布局。** 在 `desktopui/shell.go` 拆出顶部导航、项目列表和底栏组合，`types.go` 传递明确的目的地/选中项/加载状态。修正条件 chrome、空状态卡、分组和状态行；迁移显示偏好、折叠与宽度持久化；底栏补 Usage、Hosts、Help、Settings 的真实面板与菜单。
5. **收齐首页与基础样式。** 在 `desktopui/home.go`、主题与图标模块中按原版 token 迁移网格、文字和状态。先确认字体度量和可用内容宽度，再处理换行，不通过修改文案或加硬编码换行掩盖差异。宽度缩小时沿用原版 dock/overlay 和内容预算；关闭边栏后仍能从内容区恢复。
6. **完成非视觉证明后汇报。** 默认入口、加载/失败/空/部分成功状态和切换恢复全部可运行，才汇报准备进入视觉验收。按用户要求，当前不打开验收板、不索要画面判定；之后由用户确认进入验收阶段。

以上为修复顺序，不缩小原重构范围。History、Command center、Schedules、Usage 是边栏动作完整性的依赖，不能再自行标成“本轮范围外”。插件客户端、Mermaid 等已明确延期项继续延期；它们不阻塞内置入口实现。

### 尺寸规则与证据要求

- 不把某张截图的导航宽度固化为默认值。320 是原方案的偏好宽度；对照时两个应用必须使用同一保存宽度。resize 后重开恢复，临时钳制不覆盖保存值。
- 指针紧凑导航行的 `minHeight` 为 28，纵向 padding 为 4；最小高度已经包含 padding，不能再推算为 36。顶部分组间隔为 2、普通顶部内距为 8、底部为 6；拥有 chrome 时顶部规则不同。触控尺寸从原版控制尺寸规则取值。
- 原版 compact 行外层横向 padding 8、按钮内层横向 padding 8，图标与文字间隔 8；分组、项目行与底栏分别核对文字和图标的对齐线。实际渲染框尺寸用于验证，不把源码最小值当作最终像素尺寸。
- 空状态卡按 `empty-states.tsx` 的卡片与动作行迁移；Footer 的 iconButton 尺寸取原版 density，不能直接沿用所有原生按钮统一 28 的便利值。
- 对照矩阵：1440×900、1100×760、窄桌面窗口；浅色/深色；空项目、含项目、过滤为空、主机离线、三卡/四卡；导航展开/隐藏/恢复、长列表滚动。图片记录逻辑尺寸与物理像素，DPR 不同时先归一再比较。
- 每个区域记录位置/宽高、文字基线、图标边界、颜色 token、边框和交互状态。几何目标为相同逻辑尺寸；跨渲染器的字形抗锯齿差异单列，不能用来豁免缺行、顺序错误、错误换行或不同布局。
- 非视觉验证覆盖真实动作结果：新建进入正确项目；历史分页无遗漏且打开正确会话；Command center 键盘执行；Schedule 保存/启停/删除确认；Usage 加载与失败；Hosts 设置/连接；Help 打开目标；重开恢复偏好。测试只补到现有相关 suite，运行修改的具体文件及相关包检查；不运行全仓测试。

### 完成判定与现有证据

本方案本身的交付是可执行的差距、依赖和验收清单，不意味着产品已实现。实现状态分为源码已接入、定向行为已验证、实际窗口证据已取得、用户视觉通过；四者分别报告。编译和 vet 不能证明视觉对齐。

现有证据目录为 `.ryugi/artifacts/artboard/verify-native-desktop/pages/home/`：`comparison.png` 是原版 RN 浏览器与旧 native 首页的对照图；`interactions.mp4` 是此前首页流程录屏。它们用于定位差距，不是本次修订后的通过证据。历史 `/tmp/paseo-sidebar-aligned.png` 即使仍存在，也只展示一个 New workspace 的不完整边栏。

非视觉清单完成后先报告剩余阻碍，再进入用户批准的视觉验收阶段。届时每组给真实 Electron/MyGo 同状态截图，交互模块附录屏；缺目的地、无动作 Help、错误 New workspace 语义、缺 Usage 或错误 footer 顺序均直接判未完成。macOS/Windows 没有实机证据就保持未验收，Mermaid 保持暂停。
